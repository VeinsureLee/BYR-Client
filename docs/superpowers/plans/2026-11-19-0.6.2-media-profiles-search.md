# 0.6.2 媒体、资料与用户搜索实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 0.6.2 中统一 PC/Android 的图片、动态头像、用户资料展示，并提供可用的精确用户搜索入口。

**Architecture:** 保持图片地址安全解析和下载在 `core/forum`，PC 继续复用现有 `ui.VideoPlayer`/图片 Modal，Android 增加受缓存管理的 GIF 帧播放器和图片查看路由。用户资料继续使用现有 `forum.User` DTO；用户搜索第一版采用服务端已有的精确 `/open/user/query/{id}.json`，UI 明确标注“输入完整用户名/ID”，不伪造不存在的模糊搜索 API。

**Tech Stack:** Go 1.27.4、Gio v0.10.3、MyGo v0.9.1、`image/gif`、`image/draw`、现有 `forum.FetchAsset`、`content.Parse`、`httptest`、headless preview。

## Global Constraints

- 基线为提交 `fe34dbb`（0.6.1）；0.6.2 改动完成前不改版本号、不发布。
- 所有媒体请求必须继续经过 `forum.AssetURL`/`forum.FetchAsset` 的可信源和 token 注入规则。
- Android 图片下载上限继续为 32 MiB；GIF 必须限制帧数、总像素和单帧内存，避免手机内存峰值。
- 动态头像不能阻塞页面布局；加载失败必须回退首字母头像。
- 用户搜索不得把文章搜索结果冒充用户列表；第一版输入完整论坛 ID，返回一个 `forum.User` 详情。
- 测试全部使用本地 HTTP/内存图片 fixture；不抓取真实账号头像或用户资料。
