# 0.6.2 交互反馈、刷新与跨端对齐实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans (recommended) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让点赞/踩/回复/复制/收藏/刷新具备明确的图标化反馈和按压感，并让 PC 与 Android 在置顶折叠、投票竞猜可用性、刷新语义上保持一致。

**Architecture:** 将按钮反馈拆成“可观察状态”和“视觉过渡”：共享业务层只负责服务器确认后的状态，Android/PC 各自负责按压、成功提示、图标/计数布局。刷新操作统一为“清空当前模型 → 请求当前页 → 成功后回到第一页并滚到顶部”，失败时显示重试而不保留可操作旧内容。投票/竞猜入口由当前主题资源预检决定，PC 复用 Android 的资源确认规则。

**Tech Stack:** Go 1.27.4、Gio v0.10.3、MyGo v0.9.1、`widget.Clickable`、Gio `op.InvalidateCmd`/时间状态、MyGo `Pressed`/`Hovered`、`forum.Vote`/`forum.Bet`、本地 `httptest`。

## Global Constraints

- 基线为 `fe34dbb`/0.6.1；不要在所有 0.6.2 任务通过前修改版本号或发布。
- 评价成功状态必须以服务器响应/已确认的 0500 匿名规则为准；不能仅靠 UI 动画伪造成功。
- 所有写操作仍禁止自动重试；复制、刷新、收藏成功必须提供可观察反馈。
- 主题刷新失败时不得继续显示可以点赞、踩、回复、复制的旧楼层。
- 投票/竞猜按钮只能出现在已确认资源属于当前主题时；普通主题不得显示入口。
- PC 和 Android 的置顶折叠语义统一：置顶主题/置顶楼层默认折叠，手动展开；状态按 Route/分页隔离。
