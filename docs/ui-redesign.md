# BYR Client 界面与滚动体验设计

适用基线为 `cc7fe4d`（0.6.3），覆盖 MyGo 桌面端和 Gio Android 端。界面以论坛阅读为中心。浅色使用近白底与白色阅读面，深色使用近黑的中性底与分层灰面。两种模式共用字号、间距和交互层级，北邮蓝集中用于主操作、选中态、链接和焦点。窗口可以铺满屏幕，帖子正文按可读行宽排版。

## 参考与现状

原版的主要参考是仓库中 Go 改写前的 Flutter 提交 `5328eba`。用 `git show 5328eba:lib/app/byr_app.dart` 可看到 Material 3、`#0A5CBF` 种子色和主题模式。桌面工作区在 `lib/platforms/desktop/forum_workspace.dart`，手机导航在 `lib/platforms/mobile/mobile_home.dart`，文章在 `lib/features/thread/thread_screen.dart`。沿用原版的分区、版面、主题、楼层阅读路径，以及宽屏导航轨道、窄屏底部导航、楼层作者和引用关系。原版工作区中的固定栏宽和楼层卡片密度由下文的尺寸规则重新定义。

`ref/report/app/home-content.md` 和 `ref/report/app/media-local.md` 提供 4.0.0 APK 的导航、正文和图库静态证据。`ref/` 是本地参考目录，其他检出环境可以通过 Git 历史重现上述 Flutter 源码依据。视觉方向采用 ui-ux-pro-max 中适配浅深两色的简洁网格、清晰排版和低成本动效，中文字体与色值依据当前项目另行确定。长列表建议来自技能的通用规则和现有 Go 实现。

以上色对已用相对亮度公式计算。浅色和深色的主文字／主表面分别为 16.42:1、14.92:1，弱文字／页面背景为 5.76:1、8.58:1，品牌文字／选中背景为 5.54:1、7.65:1，品牌填充文字／主按钮为 6.37:1、8.83:1。两端普通文本目标为至少 4.5:1，必要图标、焦点和控件边界目标为至少 3:1。焦点环使用 2 DIP/dp，在实色主按钮外留 2 DIP/dp 间隙。弹窗遮罩用黑色叠加，建议浅色 48%、深色 64%，以实际合成结果和焦点可见性验收。 [W3C 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [W3C 非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

- 间距用 `4 / 8 / 12 / 16 / 24 / 32`。控件圆角 8，阅读引用或媒体圆角 12，浮层圆角 16。以连续表面和细分隔线组织主题列表及楼层，带边界的容器用于引用、附件、表单分组和弹层。
- 每页突出一个主操作，例如搜索、发布或发送。收藏、返回、刷新用普通按钮或有名称的图标。置顶、未读、选中使用文本或图标配合颜色。轮廓图标使用现有 MyGo SVG 与 Gio 矢量资源，普通图标 18–20，导航图标 22–24。论坛表情保留在内容和编辑区。
- 桌面普通按钮最小 36×36 DIP，Android 实际触控区至少 48×48dp，相邻楼层动作通常留 8dp。窄屏可把复制、编辑和删除归到更多菜单。图标按钮提供可读名称，收藏和置顶展开提供状态，输入保留可见的字段名。桌面键盘焦点进入滚动区和弹层后保持可见，弹层关闭后回到触发控件。 [Android 触控区规范](https://support.google.com/accessibility/android/answer/7101858)
- 桌面支持跟随系统、浅色和深色，保持现有高对比度和减少动态效果适配。映射 MyGo 的系统强调色时复测有效色对，常规模式使用 BYR 品牌色。Android 先完成手动浅深色与系统栏同色，接通并验证系统夜间模式变化后再显示「跟随系统」选项。存储继续读写现有 `theme` 数值 `0/1/2`。

## 中文排版

桌面单位是 DIP，Android 的字号与行高用 sp、布局用 dp。表中的尺寸为字号／行高。

| 用途 | 桌面 | Android | 字重 |
| --- | --- | --- | --- |
| 主题完整标题 | 26 / 34 | 22 / 30 | 600 |
| 页面标题 | 20 / 28 | 20 / 28 | 600 |
| 列表题名 | 16 / 23 | 16 / 23 | 500 或可用的 600 |
| 帖子、信件正文 | 16 / 26 | 16 / 25 | 400 |
| 导航、表单、按钮 | 14 / 20 | 14 / 20 | 500 |
| 时间、楼层、辅助文字 | 12 / 18 | 12 / 18 | 400 |

继续使用现有 Noto Sans SC Regular 作为可离线的中文底字。先验证两个框架实际选中的字面，确有需要时补经授权、覆盖中文的 Semibold 字面，并检查安装包体积、字体许可和缺字回退。Gio 使用 `font.Normal`、`font.Medium`、`font.SemiBold`、`font.Bold` 等具名常量。当前固定的是 Gio v0.10.3，该版本的 `font.SemiBold` 值为 200，`font.Bold` 值为 300。 [Gio 字重定义](https://pkg.go.dev/gioui.org@v0.10.3/font#Weight)

系统字号与应用 `FontScale` 各应用一次。桌面显式字号走统一换算，继承字号走 MyGo 已应用系统偏好的主题配置。Android 从 `app.NewContext` 的 `PxPerSp` 乘应用字号比例。纵向容器依据文本测量增长。列表主题最多显示两行，并提供完整标题语义。详情标题和正文按自然换行完整呈现，长链接和连续英文可在必要处折行。使用含中英文、全角标点、表情、数字和 UBB 的同一组夹具检查两端。

Android 的正文实现应让 `你好 [b]北邮[/b]！` 在有宽度时排成同一行，正文里的真实换行、引用和图片块按原顺序呈现。先用一个段落验证 Gio 的样式、断行和字面选择，再将其用于楼层和编辑预览。段落状态应与楼层关联，随数据、字号或宽度变化更新。桌面继续用 MyGo 的可选择富文本，并保留附件、链接、复制等现有操作。 [共享正文解析](../core/content/body.go) · [桌面正文渲染](../apps/desktop/internal/desktop/images.go)

## 全屏与自适应布局

宽度 `W` 和高度 `H` 均取应用内容区。桌面在壳层用 MyGo `Context.Size()` 读取逻辑尺寸。Android 用 `app.NewContext` 生成的约束及 `gtx.Dp` 判断断点，系统栏、刘海和 IME 的 inset 由入口处消费一次。分栏前先验证扣除导航、间隙和左右留白后的内容宽度。

| 平台 / 宽度 | 导航 | 工作区 |
| --- | --- | --- |
| 桌面 `720 ≤ W < 1000` DIP | 64 DIP 图标栏，工具提示和可访问名称保留 | 16 DIP 页边距。分区树收进「分区」入口，以抽屉或独立选择页呈现。各主页面单栏。 |
| 桌面 `1000 ≤ W < 1440` DIP | 176 DIP 图标加文字 | 24 DIP 页边距。首页空间允许时展示 200–224 DIP 分区树，旁边是版面列表。帖子和表单在内容区内居中。 |
| 桌面 `W ≥ 1440` DIP | 184 DIP 导航，32 DIP 页边距 | 版面进入主题时可启用 320 DIP 主题列表与阅读列，列间距 24 DIP，阅读列至少 640 DIP。搜索、提醒或历史直接进入主题时按单列阅读。 |
| Android `W < 600` dp | 五个底栏位置，栏高至少 64dp | 内容填满宽度，320–359dp 用 12dp 页边距，360dp 起用 16dp。阅读、编辑沿用沉浸一级详情。 |
| Android `600 ≤ W < 840` dp | 左侧 72dp 导航轨道 | 24dp 页边距，单内容列。轨道同样保留分区、搜索、发帖、消息、我的。 |
| Android `W ≥ 840` dp | 左侧 80dp 导航轨道 | 若扣除轨道、双侧各 24dp 留白、16dp 间距后仍放得下 280dp 列表和 400dp 详情，版面和消息可展示两栏。其余页面沿用单内容列。 |

- 桌面阅读列上限 760 DIP，Android 阅读列上限 700dp，登录表单上限 420 DIP/dp，编辑表单上限 820 DIP / 720dp。以居中约束形成留白，导航和页面背景覆盖窗口。单列浏览页使用可用宽度，长帖中央列从 16 号正文开始校对实际行宽。
- 桌面先完善紧凑布局并验证 720×480，随后将原生最小宽度由 960 改为 720 DIP。对话框最大宽高取当前视口减双侧边距。较矮窗口中保留关闭和确认，超出高度的内容区域可独立滚动。
- Android 顶栏以 56dp 为下限，触控区包含在测量高度内。输入法打开且可用高度不足时，在搜索和聊天输入态暂时隐藏底栏，输入框和提交按钮保持可达。横屏与分屏下若 `H < 480dp`，说明、筛选和工具栏随内容滚动，仅保留必要的返回及当前提交动作。通过真机的横屏、分屏、IME 与返回验收后再解除竖屏限制。
- 两端高密度列表用可见行构建，行高由题名和元信息算出。详情顶部栏、分页和主滚动区分配高度。低高度或大字号时将次要动作收进有名称的菜单，保证正文与主要控件可达。分栏时每个并列窗格各有滚动区。图片查看器支持独立平移和缩放，并保留退出与保存入口。
- UI 断点切换复用导航身份、列表锚点、选中版面和编辑缓冲。仅宽高变化时复用已加载的数据和请求。原版参考的分栏以当前选中列表上下文为前提。

## 页面与交互

| 页面 | 内容安排与行为 |
| --- | --- |
| 分区、版面、时间线、十大、收藏 | 分区按可发现的入口→子分区→版面组织。Android 现有分区模块入口保留，横向页签可以滚动，选中项自动进入可见区且可点击切换。主题行以题名为主，用一行次文显示版面、作者、时间和回复数，置顶合成默认折叠的一组。时间线与收藏分别显示。 |
| 搜索 | 保留全站标题、用户、AI 三种入口。按模式显示字段和提交动作，AI 未配置使用静态说明。区分尚未搜索、加载中、空结果、失败和部分结果。进入主题或用户页再返回时保留模式、已提交查询、页码和位置。 |
| 主题阅读 | 顶栏显示返回与简短上下文，全文标题放在滚动区开头。正文每层依次为头像、作者与楼层信息、回复对象、正文、附件和动作。收藏放主题级，赞／踩和回复放楼层级。置顶楼层的一行摘要可展开。保留通知跳目标楼层、匿名显示与实际权限。 |
| 消息、信箱、提醒 | 社交入口按当前能力分为联系人、收件箱、发件箱、回复、@。列表保留未读、方向、发件者和时间。聊天维持收发方向和长文展开，键盘弹出时保留输入区与可达的最后一条消息。 |
| 发帖、回复、编辑、写信 | 标题、目标版面或收件人、引用、输入、工具和附件按任务顺序摆放。大窗口可以并列编辑与预览，紧凑布局切换查看同一草稿。发布与草稿状态在各自位置反馈，输入错误贴近字段。 |
| 登录、我的、设置、账号 | 登录表单提供标签及密码粘贴，窄高窗口可滚动。我的页面按个人资料、阅读历史、账号和设置组织，版本放入「关于」。账号切换完成时刷新个人与列表状态。 |

Android 0.6.3 源码在登录、恢复会话和切换账号后进入今日十大，底栏实际顺序为分区、搜索、发帖、消息、我的。当前系统返回先关闭查看器或返回到栈顶上一页，从其他标签根页回搜索，搜索根页维持二次退出。重排导航外观时沿用这些行为，Android README 中的首屏描述早于当前实现。 [登录与恢复](../apps/android/app/internal/ui/app.go) · [账号切换](../apps/android/app/internal/ui/accounts.go)

按下立即反馈，普通颜色过渡建议 100–140ms，菜单出现或关闭 120–180ms。对宽高、间距、列表项位置保持瞬时布局，滚动跟随框架输入。首次读取较慢时在对应区域呈现静态骨架。重新读取期间保留已有内容，通知反馈覆盖空白或预留区，避免将正文顶下去。显式刷新按当前约定回到第一页和列表顶部，后台更新或返回页面时保留阅读位置。失败保留可恢复的页面数据，重试沿用相同参数。减少动态效果模式静态呈现，Android 尚未接通系统信号时默认使用简短的静态按压反馈。

## 滚动性能

| 顺序 | 代码依据与行动 | 可以检查的结果 |
| --- | --- | --- |
| 1. 采样 | 用同一离线数据，在当前版本记录长贴、版面、聊天和编辑器的帧时间、长帧、分配量及请求次数。桌面采集原生窗口，Android 采集真机。 | 确定主要开销来自应用构建、文字排版、缓存、图片解码、窗口呈现或磁盘中的哪一段。 |
| 2. 降低列表每帧工作 | 双端保留 `ui.List` / `material.List`。主题数据到达时算出回复关联、预览和可见行的正文分段，按账号、楼层 ID 与正文及附件版本更新。纯滚动复用结果。桌面首页全部版面、历史、联系人等仍用 `ui.Scroll` 的长列表，按采样优先改为虚拟列表。 | 稳态滚动中未变正文的 `content.Parse` 增量为 0。长列表构建量随可见行和少量预读增长。列表留有稳定的业务 ID，避免行序号变化错用交互状态。 [Gio 列表](https://pkg.go.dev/gioui.org@v0.10.3/layout#List) |
| 3. 固定媒体占位 | 有媒体尺寸时按宽高比预留，缺尺寸时首版可用等宽 4:3 占位并设高度上限。展开原图在图片查看器完成。使用账户隔离、按尺寸归类的缓存和在途去重，将下载及解码放入固定并发队列。 | 缓存命中、加载、失败时楼层布局稳定。若未知尺寸最终改变行高，按首个可见楼层 ID 和偏移校正。连续通过大图时资源曲线回落到设定预算。 |
| 4. 合并重绘 | Android 当前每帧遍历 `a.images` 停止动画，随后给可见 GIF 重新设置定时器。改为提交一份可见动画集合，通过一个下一帧调度器唤醒，只推进当前可见项。桌面记录播放器回收并验证不可见项停播。 | 空闲静态页、切走的页和后台页面没有持续的 GIF 重绘。快速滑动能暂停可选动画，停稳时恢复。 |
| 5. 移开同步 I/O | 编辑器里的草稿写盘、状态读锁、Android 更新队列的连续回调和 GIF 解码都要列入样本。逐帧只应用有限个数据提交，草稿写后台合并，并在离开与发布前按约定落盘。 | 滚动和输入路径没有同步文件写入。键盘输入与保存成功互相独立，退出与发布的落盘约束通过专项回归。 [草稿与任务设计](go-architecture-refactor.md#生命周期与持久化) |

路由锚点以账号、页面、版面／主题或会话、页码、查询与标签区分。记录首个可见项的稳定 ID 和偏移。选中楼层仍存在时优先恢复该锚点，内容被删除时使用相邻的有效行。返回、主题换色、窗口跨断点分别验证。框架内部生成的行索引或像素位置可以辅助恢复同尺寸布局，宽度或字号变化时用业务 ID 重新定位。

使用同一台设备、刷新率、数据和滚动脚本做前后对照。建议每个场景连续测 3 次，每次 30 秒，保留冷缓存和热缓存数据。以 60Hz 为第一档，目标是至少 95% 的滚动帧赶上对应 16.7ms 的呈现周期，热缓存期间应用侧构建与提交 p95 目标不超过 8ms，连续滚动无超过 50ms 的应用侧停顿。更高刷新率按实际帧预算，若平台采样只覆盖应用布局，则单列布局耗时。Android 可用 Perfetto 记录应用自有布局和解码区间，只有追踪实际覆盖 Gio 的呈现层时才用 FrameTimeline 判定呈现达标。 [Perfetto FrameTimeline 与采样限制](https://perfetto.dev/docs/data-sources/frametimeline)

## 实施与验收

1. 更新截图夹具并记录现状。对照以下矩阵建立常用页面的浅深色样本、主要控件边界、滚动基线和用户设置。
2. 落地颜色、字号、组件状态和响应式壳层。先完成登录、分区／版面、主题三个切片，再覆盖搜索、消息、编辑器和设置，核对每页只呈现一个主标题及主要操作。
3. 按采样优化正文、媒体和草稿任务，完成阅读位置、动作保持与异步状态回归。最后接入宽屏双栏、可用的系统偏好与 Android 横屏。
