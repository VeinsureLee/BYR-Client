# Android：Fyne / Gio 的区别与选择方法

**当前决定：正式框架待定，优先验证 Gio。** 所有者优先考虑自定义阅读交互和绘制控制，
因此先建立 Gio 探针；这不等于已经决定生产 Android 应用必须使用 Gio。

## 框架差别

| 维度 | Fyne | Gio |
| --- | --- | --- |
| UI 模型 | 保留控件对象、容器和布局，通过控件 API 更新 | 即时模式：保留必要交互状态，在布局/绘制阶段描述当前界面 |
| 常规控件 | 现成控件和组合布局是主要开发入口 | 提供布局、输入、列表、选择文本和 Material 组件，也能直接组合绘制操作 |
| 自定义组件 | 可扩展控件并编写 Renderer；能定制，不只是套默认主题 | 更直接控制布局、绘制、手势和状态；适合先探索定制交互 |
| 工程取舍 | 常规表单、列表、对话框通常更容易从现成组件起步 | 定制空间大，同时需要更主动管理交互状态和绘制行为 |
| Android 构建 | Fyne CLI 的 `package -os android` | `gogio -target android`；也支持 AAR 集成方式 |
| 系统能力 | 核查框架覆盖范围，未覆盖部分写 Android 适配 | 同样需要核查权限、文件选择、分享、返回行为等系统能力 |
| 当前仓库验证 | 仅保留文档对照，未实现本轮 Fyne 探针 | v0.10.3 独立模块，已提供离线技术探针与构建入口 |

关于开发成本与适用方向的判断是工程判断，不是两者的性能测试结果。不能仅凭
“即时模式”“GPU 绘制”就认定 Gio 滚动更快，也不能仅凭有 RichText 控件就认定
Fyne 已满足论坛的文字选择、图文和输入要求。

官方资料：[Fyne 控件列表](https://docs.fyne.io/explore/widgets/)、
[Fyne 自定义控件](https://docs.fyne.io/extend/custom-widget/)、
[Fyne Android 打包](https://docs.fyne.io/started/mobile/)、
[Gio 布局](https://gioui.org/doc/architecture/layout)、
[Gio Android 构建](https://gioui.org/doc/install/android)。构建以仓库锁定版本及实际工具
参数为准，不直接照搬可能对应不同版本的 SDK/JDK 示例。

## 针对当前项目的选择顺序

1. 先用 Gio 验证自定义阅读所依赖的输入、选择、长列表、绘制和生命周期基础能力。
2. 必测项通过后，结合你实际确定的交互方案，估算需要自建的组件和 Android 适配量。
3. 若关键能力不稳定，或需要长期维护大量底层适配，再做 Fyne 的同条件探针，而不是
   直接假定 Fyne 更好或更差。
4. 确认框架后，再建立生产 Android 模块、版本/签名策略和功能入口。

选型依据优先级应是：**必要体验正确 > 可维护性与实现成本 > 性能实测 > 框架偏好**。
具体产品页面、功能模块及操作顺序不属于这个技术比较的预设内容。

## 必须实测的能力

- 中文输入法组合输入、候选提交、换行、选区替换，以及键盘对可视区域的影响。
- 长按/拖动选择、跨行文字选择、复制和系统交互菜单。
- 长列表快速滚动、可变高度、图片加载后的重排、返回后的阅读位置。
- 自定义手势与滚动/选择之间的冲突处理。
- 系统返回键或手势、前后台切换、旋转/进程重建后的状态。
- 所需文件选择、分享、通知和其他系统能力能否保持清晰的平台边界。

当前探针没有覆盖网络图片、附件选择、分享、通知、进程重建或正式状态持久化。
这些项目不能因为 APK 能生成或控件能布局就标为通过。
